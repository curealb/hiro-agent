- `agent.py` / `errors.py`：准备动作在 Run 和任务日志之后、首个模型请求之前执行；`RunSuspended` 结束本 Run 为 paused，并配对全部已声明工具；持久 task 身份独立于委派 call ID。
- `tools.py`：可选 contextual gate 在 schema 校验之后、tool.started 之前执行。持久审批挂起通过明确异常传递；保存的操作仍经过原执行器、预算、schema、白名单、当前权限复查。持久任务的失败工具写结果后停止 Run，防止未知结果后继续调用；旧无 gate 路径保留。
- `bootstrap.py`：可选 `create_session` 为预分配 Session ID 建日志；`persist_bot=False` 加载实时保存配置，避免 worker 用旧配置覆盖权限更新；提供 model 与 tool gate/registry 注入接缝，旧默认入口不变。
- `budget.py`：直接同步 checkpoint callback，错误传播，不使用 EventBus；`seal()` 在终态写入前冻结 elapsed，避免心跳在 run.ended 写入期间超过最终指标。原无 callback Budget 保持可用。

- `tests/test_kernel_cli.py`：3 项真实子进程 CLI 测试，包括持续 worker、提交 CLI 退出、worker 停止/重启、跨进程审批和提问、重复答复。
- `docs/kernel/USAGE.md`：可运行命令、独立 worker 管理、权限和预算规则、恢复边界；本交接记录。

## 接口与持久执行流程

```python
kernel = KernelRuntime(workspace, model_factory=None)
# model_factory: Callable[[Config], ModelService]，可注入离线确定性模型
kernel.bots.save(config)
task = kernel.tasks.submit(TaskSubmission(bot_id="writer", text="..."))
worker = kernel.worker(poll_interval=0.5)
await worker.tick()  # 至多一个任务；首次先恢复遗留 active Run
await worker.recover()  # 对账后唤醒已回答的交互
await worker.serve(stop)  # 独立进程持续循环
await worker.close()  # B1 锁在执行停止和清理后释放
```

运行使用 SQL 预分配的 Run/Session ID。ask_user 工具参数为 `{"question": "..."}`，须加入 Bot 白名单。修改工具自动创建 approval；提问创建 question。交互与规范参数、权限版本、Task/Bot/Session/Run/call 关联先持久保存，随后 JSONL interaction.waiting，旧工具调用由 Agent 结算 not_started，旧 Run 结束。多个已声明调用同样全部结算，不保留悬空 call。

答复保存后 ready 清单持续可读。批准的新 Run 使用新的唯一 call ID 写 prepared_operation assistant 声明，并经相同 ToolExecutor 执行保存的规范化参数；执行完成之后才允许模型请求。一次性授权在当前权限检查下消费，消费失败不会降级到普通审批。拒绝、撤权、权限撤回又恢复、无效工具参数均有可查询失败终态；终态清理未消费交互，答复历史保留。问题先写 interaction.answer，再消费答案并追加 task.continued 用户输入。重复答复不重复执行或无限唤醒。

预算来自 Task 原始上限减累计 metrics。root Budget 每次计数变化同步 checkpoint，父指标已经包含子 Agent，不再次添加；每 100ms 心跳保存 active elapsed。Run 终态前 seal，结束后停止心跳，等待不计费。持久失败向 worker 传播并停止本轮，不伪造普通成功/可重试状态。崩溃对账复用 B1 的逐字段最大值，日志与已记 SQL 用量取下限，不能靠重启退还额度。

## 四个切点与保守停止

1. SQL `claimed` 且日志没有对应 run.started：回收占位 Run、重新 queued；新 Run ID、预算保留。worker 已把 SQL 标为 started 后但 JSONL 尚未开始的小窗口则保守 needs_reconciliation，不能与纯 claimed 混同。
2. JSONL run.ended 已落盘、SQL Task 未 finish：验证 Bot/Task/Run/Session 关联，读取终态与指标，幂等 reconcile，不调用模型/工具。
3. 审批/答案已保存、Task 未 wake：每次启动和轮询 ready，再幂等 wake；最多一次授权/答案消费。
4. tool.started 已落盘、tool.result 缺失：先 recover_delegations，再 recover_session；真实工具结果 outcome=unknown 令 Task 进入 needs_reconciliation，不可自动领取。

正常运行中返回的未知工具结果也由真实 JSONL outcome 检测，通过已批准的 TaskRunOutcome.unknown_side_effect 让 B1 worker 走 reconcile。不能按 reason 文本猜测。损坏/忙碌日志停止 worker；已开始的 SQL Run 缺日志保守待核实，不建新空日志重放。

授权已消费但工具未开始的崩溃窗口不会返还授权。有日志且证明未启动时中断 Run 安全失败，检查后可重新提交任务取得新审批。答案消费后、用户输入记录之前若失败，同样安全失败；答案已在 InteractionStore 和 interaction.answer JSONL 保存，可人工取回再提交，不悄悄复用答复。硬崩溃最后未落盘的短时间片无法精确重建，恢复保存已有 SQL/JSONL 用量下限；已开始的中断 Run 不自动获得新预算或重跑。这些行为均写入 USAGE。
