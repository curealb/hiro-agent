## 文件与公共 API

公共类型从 `hiro_agent.routines` 导入。接口均同步；`tick` 不执行模型、工具、Run 或 Session，只调用 `TaskStoreService.submit(TaskSubmission)`。

```text
RoutineStore(database: KernelDatabase, bots: BotStore, tasks: TaskStoreService)
create(request: RoutineCreate, *, now: datetime | None = None) -> RoutineRecord
get(routine_id: str, *, bot_id: str | None = None) -> RoutineRecord
list(*, bot_id: str | None = None, enabled: bool | None = None) -> list[RoutineRecord]
set_enabled(routine_id: str, enabled: bool, *, bot_id: str | None = None,
            now: datetime | None = None) -> RoutineRecord
enable(routine_id: str, *, bot_id: str | None = None,
       now: datetime | None = None) -> RoutineRecord
disable(routine_id: str, *, bot_id: str | None = None,
        now: datetime | None = None) -> RoutineRecord
triggers(routine_id: str, *, bot_id: str | None = None) -> list[RoutineTrigger]
tick(*, now: datetime | None = None, max_triggers: int = 100) -> list[RoutineTrigger]
```

- `RoutineCreate`：`bot_id, text, scheduled_at: datetime, interval_seconds: int | None = None, enabled: bool = True, budget: BudgetConfig | None = None, metadata: dict = {}`。`interval_seconds=None` 为一次性；固定间隔必须是严格正整数秒，布尔值、字符串和小数均拒绝。不能表示首个后续时间的极大间隔拒绝。定义不提供修改 API；更换文本或计划应停用旧例程并创建新例程。
- `RoutineRecord`：`id, definition: RoutineCreate, enabled, next_scheduled_at, last_scheduled_at, last_task_id, created_at, updated_at`，另有 `bot_id` 属性。`definition.enabled` 是创建时的原始值；当前启停状态读取顶层 `enabled`。返回值是数据库快照；修改返回值的嵌套元数据不会改数据库。
- `RoutineTrigger`：`routine_id, scheduled_at, submission: TaskSubmission, task_id: str | None`。`task_id=None` 表示已接受但尚未确认提交完成的持久待提交记录；即使 Task 实际已建立，崩溃窗口中此字段仍可能为 None。`triggers()` 按计划时间返回完整触发历史，可核验提交请求与 Task ID。
- `get/set_enabled/enable/disable/triggers` 提供可选 Bot 所属检查；`list` 可按 Bot 和当前启停状态过滤。构造顺序为数据库 → BotStore → TaskStore → RoutineStore。

## 时间、补发与停用规则

所有调度时间、注入的 `now` 必须带时区，进入服务后规范化为 UTC；不接受不带时区的本地时间。SQL 排序和幂等键使用固定六位微秒的 UTC ISO 8601 表示，例如 `2026-11-02T01:02:03.000000+00:00`。CLI 应要求 ISO 8601 中包含 `Z` 或明确偏移量，或先按用户明确指定的时区转换；不能用 worker 所在机器的隐式时区猜测。`+08:00` 与对应 `Z` 时间是同一时刻。

一次性触发确认提交后，`next_scheduled_at=None` 且 `enabled=False`。已完成的一次性例程不能重新启用，防止重复触发；再次运行需创建新例程。固定间隔按上一次 **scheduled time + interval** 推进，绝不按 polling 时间推进，因此迟到或重启不造成漂移。极端情况下后续日期超出 Python/ISO 9999 年边界时，最后一个合法触发完成后结束例程。

每次 `tick` 固定一次 `now` 截止值，默认最多尝试提交 100 个触发；`max_triggers` 可取严格整数 1–1000，限制覆盖全部 Bot/例程。先处理已有 pending 记录，再按所有启用例程中最早到期的计划时间选择下一项，同一时间按例程 ID 稳定排序。每个调用最多尝试该数量，即使并发调用造成部分提交成为幂等重放也不突破限制。多个 tick 的额度各自计算。

补发不丢弃中间间隔：例如每 3 秒一次，当前迟到 10 秒，`max_triggers=2` 首轮提交第 0、3 秒，下一轮提交第 6、9 秒，之后计划为第 12 秒。即使错过很久，单次工作仍有上限；剩余积压保留给后续轮次。因此很大的历史积压可能先于更晚到期的其他例程处理，这是明确的最早到期优先策略。

停用只阻止**新的触发接受**，保留原 `next_scheduled_at`；重新启用继续按上述有上限策略补发停用期间的间隔。**已经持久化为 pending 的触发属于已接受工作，停用不会撤销，会继续通过 TaskStore 提交。** 即使系统时钟回拨到它的计划时间之前，也会对账这项已接受工作。停用与正在提交竞争时，提交完成后的计划推进保留当前停用状态，不会意外重新启用。已创建 Task 需要取消时使用公共 Task 取消入口。

## 提交与崩溃恢复

触发分三段执行，每段只使用短同步事务：

1. 在 C3 事务内选取计划，持久化唯一 `(routine_id, scheduled_at)` 的 pending 记录，保存完整规范化 `TaskSubmission`，但不推进计划。每个例程最多一项 pending。
2. 事务外调用公共 `tasks.submit`；幂等键为 `routine:{routine_id}:{UTC scheduled time}`，`source="routine"`。元数据为 `routine_id`、`scheduled_at`、`routine_metadata`，用户元数据封装在最后一项内，不可覆盖归属信息。显式 budget 保持创建时快照；省略 budget 时由 TaskStore 在首次提交时使用 Bot 默认预算。
3. 在同一个 C3 事务内写 pending 的 `task_id` 并推进例程时间。若另一连接已经确认同一 Task，不再推进或再次返回该触发。

“接受后/Task 提交前”退出会留下 pending；“Task 创建后/计划推进前”退出同样留下 pending。重启重交完全相同的请求，TaskStore 返回原 Task；不会先推进导致任务丢失，也不会改变请求引起幂等冲突。确认更新失败会回滚 task_id 和计划推进，原 Task 仍可重新对账。异常原样向调用者传播；先前成功确认的触发保持提交，下一轮可继续恢复。

`tick()` 只返回由本调用成功首次确认的触发，并发输掉确认竞争的调用可能返回空列表。它不是持久事件流；不可依赖返回值完成记忆或其他必须持久消费的工作，应查询触发历史或 Task API。没有永久领取锁或过期租约，故进程死亡后下一次 tick 可立即重试。

## C4 接入示例

下面是服务用法，未声明尚未接入的 CLI 命令。独立 worker 生命周期中应在正常任务领取前周期性调用同一个 `routines.tick()`；使用默认时间或注入带时区的测试时间，不需要新增模型执行入口。C4 负责持续 polling 和 CLI。

```python
from datetime import UTC, datetime
from pathlib import Path

from hiro_agent.bots import BotStore
from hiro_agent.durable_tasks import TaskStore
from hiro_agent.kernel_db import KernelDatabase
from hiro_agent.routines import RoutineCreate, RoutineStore

database = KernelDatabase.for_workspace(Path("/path/to/workspace"))
bots = BotStore(database)
tasks = TaskStore(database, bots)
routines = RoutineStore(database, bots, tasks)

# inspector must already exist in BotStore.
scheduled = datetime.fromisoformat("2026-11-02T09:00:00+08:00").astimezone(UTC)
routine = routines.create(
    RoutineCreate(
        bot_id="inspector",
        text="Inspect the workspace and write a report in your final answer.",
        scheduled_at=scheduled,
        interval_seconds=3600,
    )
)
submitted = routines.tick(now=scheduled, max_triggers=10)
assert submitted[0].task_id is not None
routines.disable(routine.id, bot_id="inspector")
routines.enable(routine.id, bot_id="inspector")
history = routines.triggers(routine.id, bot_id="inspector")
```
