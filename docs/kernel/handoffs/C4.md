## 运行时 API 与生命周期

```python
from pathlib import Path

from hiro_agent.kernel_contracts import TaskSubmission
from hiro_agent.kernel_runtime import KernelRuntime

kernel = KernelRuntime(
    Path("/absolute/workspace"),
    context_max_chars=64_000,
    context_max_messages=64,
)
# writer 已经由 bot-save 保存。服务入口均使用同一数据库。
note = kernel.memory.create("writer", "报告请保留可核实证据")
kernel.skills.enable("writer", "inspect")
task = kernel.tasks.submit(TaskSubmission(bot_id="writer", text="检查项目"))
worker = kernel.worker(poll_interval=0.5)
# await worker.tick()：到期触发、摘要对账、至多执行一个普通 Task。
# await worker.serve(stop)：持续定时提交和唯一 Task 执行器。
# await worker.close()：取消并收敛调度和执行后释放进程锁。
```

KernelContext 使用 Task.text 作为 current_task，恢复时仍保留原任务和最新用户答复。系统指令、原任务、最新用户与最新完整工具组不可裁剪；超限的 ContextCapacityError 经既有 Agent/HiroError 路径形成可查询 failed Task，不调用该轮模型，不通过拆工具组或重置预算继续。默认容量为消息 JSON 字符总数 64000、消息数 64，`kernel worker --context-max-chars / --context-max-messages` 可调整。

纯准备函数把参考记忆放在首个 user 之前；集成层只移动这个新生成的参考消息到原任务之后，以保持现有 provider 把首个 user 识别为 Task 的兼容性。原始历史、系统指令及工具单元顺序不变，字符数/消息数不变。每轮 fresh list/describe 让编辑、删除和禁用立即在后续投影生效；删除摘要仍保留 C1 消费凭证，重启扫描不会复活它。

“不把投影写入 JSONL”指不将参考投影追加为会被 derive_messages 重用的 Session 历史，不改变或删除原始日志。model.requested 仍保存当时的真实模型请求，包括当时存在的记忆/说明；它不参与 derive_messages。删除保证后续请求不再注入该记录，不抹掉真实审计，也无法撤回模型或工具已经引用的文本。压缩只改变本次请求，原始工具声明/结果和全部事件保持完整。

`read_skill` 参数是 `{"skill_id": "inspect"}`，工具闭包绑定当前 Task.bot_id，`skills.content` 每次核验本 Bot 已启用。Bot.allowed_tools 必须显式包含 read_skill，调用仍经过普通 ToolExecutor 的 schema、实时白名单、权限和预算逻辑，工具结果完整记录；Skill 文本不改变授权。仅启用说明不会自动执行脚本。草稿只由 `skill-draft BOT SUCCEEDED_TASK_ID` 显式生成，C2 持久创建意图与发布幂等机制负责崩溃修复，生成不启用，也不从瞬时 observer 自动生成。

KernelWorker 在 recover 后、tick 前后和持续轮询扫描 C1 sync_terminal。Task 已完成、摘要未保存时即使进程退出，下次重开仍补齐。错误不被 observer 吞掉；持久失败会停止 worker，已经完成的 Task 保留并可在重启消费。

serve 在同一个 worker 进程启动独立调度协程；每次默认最多尝试 100 个到期触发，调用 C3 RoutineStore.tick，只提交统一 Task。长任务仍由一个 TaskWorker 串行执行，定时工作会排队。调度异常设置 stop，活动 Run 走原协作取消和日志结算；受 TaskWorker.close 的屏蔽取消保护先收敛调度、再收敛执行并释放锁，异常传播给调用方。手动 tick 或 --once 只触发单轮；持续服务必须省略 --once。

C3 停用只阻止新接受，已经持久 pending 的触发继续提交。已建 Task 需另行 cancel；重新启用按计划时间有界补发停用期间全部间隔；一次性计划完成后不能重新 enable。USAGE 明确说明这一行为、UTC/时区要求和最早到期优先策略。触发历史没有清理 API。
