## 持久 API

所有入口由 `hiro_agent.memory` 导入；依赖现有 `KernelDatabase`、`BotStore` 与公开 `TaskStoreService`，初始化自己的 `memory` 命名空间迁移。只操作本模块的 `bot_memories`、`memory_consumptions` 表，不读写其他模块内部表。

准确签名如下（省略 `self`）：

```text
MemoryStore(database: KernelDatabase, bots: BotStore, tasks: TaskStoreService)
create(bot_id: str, content: str) -> MemoryRecord
get(bot_id: str, memory_id: str) -> MemoryRecord
list(bot_id: str, *, query: str = "", limit: int = 100) -> list[MemoryRecord]
update(bot_id: str, memory_id: str, content: str,
       *, expected_revision: int | None = None) -> MemoryRecord
delete(bot_id: str, memory_id: str) -> None
remember_task(bot_id: str, task_id: str) -> MemoryRecord | None
sync_terminal(bot_id: str) -> list[MemoryRecord]
task_summary(task: TaskRecord) -> str
```

`MemoryRecord` 的字段：`id: str`、`bot_id: str`、`content: str`、`kind: Literal["note", "task_summary"]`、`task_id: str | None`、`final_run_id: str | None`、`revision: int`、`created_at: datetime`、`updated_at: datetime`。手工记忆默认 `kind="note"`，没有任务或 Run 关联。摘要不可通过 CRUD 改所属 Bot 或来源，只能修改正文；修改将 revision 递增。快照与保存状态分离。

每次查询/变更都验证 Bot 存在，按指定 Bot 查询；读摘要时还通过 `tasks.get(..., bot_id=...)` 核验来源任务。没有跨 Bot 的通配查询入口。错误 Bot、未知记录、空白或过长正文、过期 revision 抛 `ConfigurationError`。delete 删除记录本身，重复删除报未知记录。正文最多 `MAX_MEMORY_CHARS=16384` 个 Python Unicode 字符，保留原文空白。list 的 query 是大小写敏感的字面子串，`%` 和 `_` 没有通配作用；按 `updated_at DESC, id DESC` 排序，limit 范围 1–1000。

`remember_task` 只接受已经结算且没有 active Run 的 `succeeded/failed/cancelled` Task。读取 Task 和有序 runs 的公开 API，使用最新 Run ID；排队即取消、从未有 Run 的任务使用内部稳定键 `no-run`，公开记录仍为 `final_run_id=None`。摘要来自持久 Task 的 text/state/reason/output，固定裁剪为最多 `SUMMARY_CHARS=4096` 字符，不调用模型，不把失败/取消写成成功。

摘要消费唯一键是 `(consumer="memory.task-summary.v1", bot_id, task_id, final_run_id)`。首次摘要正文与消费凭证在同一立即事务中保存；并发及重启重放返回同一记录。编辑后的摘要不会被重新生成覆盖。删除摘要保留消费凭证；随后 `remember_task` 返回 None，`sync_terminal` 不返回该条，故轮询不能使删除的内容复活。`sync_terminal(bot_id)` 每次扫描公开终态列表并消费，返回现存摘要（包括原来已消费的记录），无需 observer 通知，也不修改 Task/Run。C4 在启动、恢复后、任务结算后或轮询调用它，可补上“Task 已结束而摘要尚未保存”的窗口。

## 纯上下文 API

```text
prepare_context(messages: Sequence[Message], *, bot_id: str, current_task: str,
                memories: Sequence[MemoryRecord] = (), max_chars: int = 64000,
                max_messages: int = 64) -> PreparedContext
context_size(messages: Sequence[Message]) -> int
```

`PreparedContext` 为 frozen dataclass，字段是 `messages: list[Message]`、`char_count: int`、`omitted_messages: int`、`omitted_memories: int`。消息为深拷贝；列表可由调用方消费，改变它不会影响输入或原始 Session。函数不访问文件、数据库、observer 或模型。

C4 应传 `current_task=task.text`，以及当前 `session.derive_messages()`。原任务用最近一个正文相同且 `continuation=False` 的 user 消息标识；不存在时，在前导 system 消息之后显式插入原任务 user 消息。所有 system 消息、原任务、最新 user 消息（包括恢复后 `task.continued` 的用户答案）、最新完整单元必须保留。输入只含历史答案而不含原任务时，也会同时保留传入的原任务与最新答案。

assistant 的所有 tool_calls 与后续每个对应 tool result 组成一个不可分割单元，结果可以按不同顺序到达。调用 ID 必须唯一；孤立/重复/缺失结果、调用组中夹入用户或新 assistant 等非法历史直接报 `ConfigurationError`，即使这些消息本来可能被裁剪。挂起/恢复必须由既有 Session 先完成结算，prepare_context 不伪造工具执行结果。失败、unknown、not_started、恢复后新 call 的正文按原样保留或随完整单元一起裁掉。

容量是硬边界：`context_size` 精确求和每条 `Message.model_dump_json()` 的字符长度，包含角色、调用参数、结果等字段；它不声称是模型 tokenizer 的 token 数或完整请求字节数。输出同时满足 max_chars 与 max_messages。必须保留的集合自身超限时抛出 `ContextCapacityError`（继承 `ConfigurationError`），不截断系统指令/当前任务/最新工具组。C4 应将此错误转换为可查询的清晰暂停/失败结果；没有交互的暂停在现有 Task 层映射 failed。可调整调用参数，不能以删原始日志或拆工具对绕过。

优先级为：必保留消息 → 传入顺序的记忆 → 由新到旧的其他完整消息组。记忆合成一个 user 消息，标记为可能过时的参考数据，以 JSON 转义其 ID/正文；不注入为 system 指令，不改权限。调用方应传入 list 的最新优先结果。某条记忆不再能放入时停止添加记忆；某个历史组不再能放入时停止向旧历史扩展，产生确定的前缀/尾部边界。omitted_messages 只计算被省略的输入消息，omitted_memories 只计算被省略的输入记忆；插入的任务/记忆消息计入输出容量。

每次准备必须重新查询当前 Bot 的记忆；pure 函数不可能发现调用方持有的过期快照已被删除。不得把记忆投影写成会被 `derive_messages` 重用的 Session 历史消息，避免新任务携带已经删除的缓存。主代理在 C4 集成时明确：既有 `model.requested` 审计应保留当时实际请求（包括当时可用的记忆），它不参与历史消息派生；删除要求作用于未来上下文，不抹去原始执行日志。

最小 C4 接入示例（初始化 store 一次，投影每次重新查询）：

```python
from hiro_agent.memory import MemoryStore, prepare_context

memory = MemoryStore(database, bots, tasks)
memory.sync_terminal(task.bot_id)
prepared = prepare_context(
    session.derive_messages(),
    bot_id=task.bot_id,
    current_task=task.text,
    memories=memory.list(task.bot_id),
)
model_messages = prepared.messages
```

以上为接缝示例，C1 没有把它接进共享运行时。记忆更新/删除可以直接使用对应 MemoryStore 方法，下一次重新查询的投影即生效。
