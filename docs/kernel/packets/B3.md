## 核心恢复约束

- 挂起精确意图持久保存，旧调用用未执行结果结算；所有已声明调用都有结果。
- 批准后创建新 Run，通过执行器执行保存的精确操作，不能只希望模型重新生成相同调用；授权仅消费一次并绑定 Task、参数、工具与实时权限版本。
- 提问也能跨进程挂起/答复/恢复；重复答复不会重复执行或无限唤醒。
- Task 的累计模型/工具/执行时间预算跨 Run；等待不计执行时间，崩溃不免费重置预算。
- 明确 SQLite/JSONL 对账四个切点，恢复未开始的领取，但决不自动重放开始后结果未知的副作用。Run 已结束而 Task 未更新须从持久日志结算，无重复模型或工具。
- 取消/失败/权限撤回/格式错误有可观察终态；避免长锁阻塞 CLI 审批。
- 主代理已协调 B1 为 `TaskRunOutcome` 新增兼容字段 `unknown_side_effect: bool = False`。B3 必须用真实 JSONL 显式证据设置它，不能从 reason 文本猜测；worker 在 true 时走 reconcile(RunEvidence)，不会走普通 finish。读取 B1 最终交接和状态映射，未知副作用绝不自动运行。
- B2 提醒：`ready()` 包含已拒绝审批，拒绝时 consume_authorization=False 且记录仍 answered。B3 处理拒绝/终态后要妥善调用 cancel_for_task 清理尚未消费的唤醒记录并保留答复历史；避免旧拒绝不断唤醒或误取消后来新交互。

使用真实 SQLite/JSONL 和确定性离线模型测试整个流程，包含进程边界与故障注入。运行本节点组合测试及全量 Ruff、格式检查、mypy、pytest、构建。环境命令在 BASELINE.md。
