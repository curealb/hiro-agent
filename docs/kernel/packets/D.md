## 已协调的 D 设计

主代理已批准：消息按 `(source_task_id, idempotency_key)` 去重，接收方通过 TaskStore.submit 建任务；终态结果保存到唯一回传账本，再向原发送 Bot 提交关联结果任务。原任务异步完成，无需新增等待状态。结果任务本身不自动再回传；只有明确 send_handoff 才增加链全局交接计数（默认最多 8 次）。模型 send_handoff/read_handoff 固定当前 Bot/Task 所有权。

TaskStore 持有链预算账本，并在 checkpoint/finish/reconcile 的同一 SQL 事务按增量计费。TaskSubmission 可兼容新增可选 root-only chain_budget/chain_max_hops；子任务和结果任务继承、不可提高或重置。运行剩余额度取 Task/链两者较小值。旧 SQLite 任务迁移保留累计用量，既不退款也不重复计费。链额度耗尽时仍保存收件箱结果，但结果任务不得绕过额度执行，必须有明确可查询状态。D 是这些共享接缝的唯一生产写入者。

实现持久 Bot 收件箱、发送/接收关联、接收方经统一 Task 提交入口建任务、持久结果回传及 CLI 可观察路径。模型也应有明确工具/上下文入口完成交接与读取结果，工具仍受 Bot 白名单约束。结果回传必须能证明到达原发送方，包含源消息/源任务/目标任务关联与失败结果，不能仅把两个独立任务排进队列。任务/消息所有权隔离。

采用幂等消息标识和终态消费账本，覆盖发送已保存/接收任务未建立、任务已创建/消息未标记、结果已结束/未回传、已回传/消费未标记的重启切点，重复操作不重复任务或回传。避免内存 callback 成为唯一可靠路径。

往返次数/跳数与累计预算上限必须在持续的 chain ID 下持久执行，跨 Bot、新 Task、新 Run 和重启均不可重置。与 Task budget 记账共同保证不超额、不重复计费，等待仍不计执行时间；限制应能通过自动互聊的离线模型真实证明，不只有静态参数验证。已有任务累计预算和未知副作用策略保持有效。

实现并自测完整离线场景：定时巡检→报告→审批等待→重启→批准写入→交第二 Bot 审阅→结果返回；既有记忆/Skills/触发/权限可组合。更新 `docs/kernel/USAGE.md` 给出可运行命令和演示说明。运行 D 模块测试及全量 Ruff/格式/mypy/pytest/构建。环境见 BASELINE.md。保存 `handoffs/D.md`：接口/状态变化、文件、实际检查和未解问题，随后冻结生产交给全新 R4，不自行宣告最终交付。
