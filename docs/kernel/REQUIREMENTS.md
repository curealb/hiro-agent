# 最小 Grok Bot 内核：执行与验收要求

本文件是本次开发的需求与门槛记录。范围：单用户、本地单 worker、CLI、SQLite 任务状态、JSONL 原始执行日志；长期 Bot、持久任务、记忆、文本 Skills、定时触发与双 Bot 交接。保留现有 `AgentService` 作为单次执行入口。

## DAG 与所有权

`A → R1 → (B1 || B2) → B3 → R2 → (C1 || C2 || C3) → C4 → R3 → D → R4 → E`

验收失败退回原实现节点修复，再由同一阶段独立验收代理复验；通过之前不得启动下游。验收期间生产代码冻结。每个实现节点、每阶段验收都启动新的子代理，使用最小任务包，不继承聊天历史。并行实现代理只能写自己拥有的模块及测试；共享 Agent、工具执行器、Session 恢复、装配和 CLI 只有当前集成节点能修改。不得回退他人改动，接口变更先报主代理协调。

| 节点 | 职责 |
| --- | --- |
| A | Bot/Task/Run/Session 关系、公共接口、持久化边界、Bot 配置和工具白名单、旧功能基线 |
| B1 | 任务存储、提交/查询/取消、单 worker、领取、重启对账；只拥有任务存储/调度模块 |
| B2 | 审批/提问持久化、答复、一次性授权、重复答复；只拥有交互模块 |
| B3 | Agent/执行器/恢复/装配/CLI 的唯一集成写入者；提交—挂起—重启—继续 |
| C1 | Bot 独立记忆、查询/改/删、任务摘要、压缩；原始日志和工具配对完整 |
| C2 | Markdown Skills、按 Bot 启用、说明注入、成功任务生成草稿；不改变权限 |
| C3 | 一次性/固定间隔 Routines、启停、去重；统一 Task 提交 |
| C4 | 上述能力接入运行时/CLI、组合场景、文档 |
| D | 持久收件箱、交接关联、接收方建任务、结果回传、往返次数/累计预算限制 |

## 必须保持的恢复语义

- 挂起时，旧调用结算为未执行，把精确操作意图存入 Task；批准后开始新 Run。
- 一次性授权绑定任务、工具名与规范化参数、权限版本；重复答复不能重复消费或执行。
- 等待时间与执行预算分离；续跑不能重置 Task 累计预算，双 Bot 交接不能重置会话链预算。
- SQLite 与 JSONL 无跨存储原子事务。明确权威数据与对账规则，不自动重放未知副作用。
- 必须验证四个崩溃窗口：任务已领取/Run 未开始；Run 结束/Task 未更新；审批已保存/Task 未唤醒；工具已开始/结果未落盘。
- 原有配置、CLI、会话恢复、只读子 Agent 必须兼容。

## 独立验收

每阶段验收代理读取本需求、实际代码和改动，自行运行测试，可新增其专属验收测试，不得修改生产代码。报告包含基准 git revision、当前被检查文件的内容哈希、实际命令与退出状态、问题文件/行号和明确 PASS/FAIL。所有必需项通过才放行。

每阶段运行模块测试和完整检查：`ruff check .`、`ruff format --check .`、`mypy src`、`pytest -q`、构建（优先仓库 `uv run --locked ...` / `uv build`）。环境问题必须记录并解决或明确阻塞，不能把未运行当作通过。

| 门槛 | 必须证明 |
| --- | --- |
| R1 | Bot 身份持久化；执行端白名单；旧配置/CLI/恢复/子 Agent 回归 |
| R2 | CLI 退出后 worker 仍可运行；审批/提问跨进程恢复；重复答复幂等；四个崩溃窗口；未知副作用不重放；累计预算 |
| R3 | 跨任务读/删记忆；压缩保持工具配对及日志；Skills 不扩大权限；重复定时触发只有一任务 |
| R4 | 定时巡检→报告→审批等待→重启→批准写入→第二 Bot 审阅→结果返回；互聊次数/累计预算限制；完整旧功能回归 |

阶段完成后更新 README。四阶段全部通过后交付实现、使用文档和验收记录。
